## 什么是 LangChain

LangChain 是一个用于构建 AI 应用程序的开源框架。它的核心目标是**将大语言模型（LLM）与外部世界连接起来**，
让开发者能够轻松地构建基于 LLM 的复杂应用。

### LangChain 解决的核心问题

1. **统一接口**：不同 LLM 提供商（OpenAI、Groq、Anthropic、Google）有不同的 API 格式，
   LangChain 提供统一的调用接口，一次编写，随处运行。

2. **工具集成**：让 LLM 能够调用外部工具（搜索、计算、数据库查询等），
   突破纯文本生成的限制。

3. **链式调用**：将多个 LLM 调用和工具调用串联成工作流，
   实现复杂的多步骤任务。

4. **记忆管理**：为无状态的 LLM 添加对话历史和上下文记忆能力。

### LangChain 的发展历史

```
2022.10  LangChain 诞生（Python 版本）
2023.03  LangChain.js 发布（JavaScript 版本）
2023.04  LangChain 快速迭代，社区爆发
2024.01  LangServe 发布（部署工具）
2024.07  LangGraph 独立发布
2025.06  LangChain 1.0 正式发布（重大版本更新）
```

### LangChain 1.0 的关键变化

- `create_agent()` 替代了旧的 `create_react_agent()`
- 更简洁的 API 设计
- 更好的流式输出支持
- 与 LangGraph 深度集成

## 什么是 LangGraph

LangGraph 是一个**基于图的有状态工作流框架**，专门用于构建复杂的 AI Agent 和多步骤工作流。

### 为什么需要 LangGraph

传统 LangChain 的 Chain 是线性的（A → B → C），但现实中的 AI 应用往往需要：

- **条件分支**：根据中间结果决定下一步
- **循环执行**：Agent 反复调用工具直到任务完成
- **状态管理**：在多个步骤之间共享和维护状态
- **人工介入**：在关键步骤暂停等待人工确认

LangGraph 通过**有向图（Directed Graph）** 来建模这些复杂流程。

### LangGraph 的核心概念

```
┌─────────────────────────────────────────────┐
│              LangGraph 核心概念              │
├─────────────────────────────────────────────┤
│  State（状态）    → 在节点间共享的数据       │
│  Node（节点）     → 执行具体操作的函数       │
│  Edge（边）       → 节点间的连接和流转       │
│  Conditional Edge → 根据条件选择下一个节点   │
│  START / END      → 图的起点和终点          │
└─────────────────────────────────────────────┘
```

## 核心设计理念

### 1. Composability（可组合性）

LangChain 的所有组件都可以像乐高积木一样自由组合：

```python
# 组件可以自由组合
chain = prompt_template | model | output_parser

# 也可以嵌套组合
complex_chain = preprocessing | chain | postprocessing
```

### 2. Modularity（模块化）

每个组件职责单一，可以独立替换：

```python
# 只需要更换 model 参数，就能切换底层模型
agent = create_agent(
    model="groq:llama-3.3-70b-versatile",  # 或 "openai:gpt-4o"
    tools=[...],
    system_prompt="..."
)
```

### 3. Streaming-first（流式优先）

所有核心组件都支持流式输出，提供更好的用户体验：

```python
# 流式输出：实时看到 AI 的思考过程
for chunk in agent.stream({"messages": [...]}):
    print(chunk, end="", flush=True)
```

## 环境搭建步骤

### 步骤 1：确认 Python 版本

LangChain 1.0 需要 **Python 3.10 或更高版本**。

```bash
# 检查 Python 版本
python --version
# 输出示例：Python 3.12.4

# 如果版本低于 3.10，请前往 https://www.python.org/downloads/ 下载最新版本
```

### 步骤 2：克隆项目并创建虚拟环境

```bash
# 克隆项目
git clone https://github.com/your-username/Langchain1.0-Langgraph1.0-Learning.git
cd Langchain1.0-Langgraph1.0-Learning

# 创建虚拟环境
python -m venv venv

# 激活虚拟环境
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# 确认虚拟环境已激活（命令行前面应该出现 (venv) 标记）
```

### 步骤 3：安装依赖

```bash
pip install -r requirements.txt
```

`requirements.txt` 包含以下核心依赖：

```
langchain>=1.0.0          # LangChain 核心库
langgraph>=1.0.0          # LangGraph 工作流框架
langchain-groq            # Groq 提供商集成
langchain-openai          # OpenAI 提供商集成
langchain-google-genai    # Google Gemini 集成
langchain-community       # 社区工具和集成
langgraph-checkpoint-sqlite  # SQLite 检查点存储
python-dotenv             # 环境变量管理
```

### 步骤 4：配置 API Key

#### 获取 Groq API Key（推荐，完全免费）

1. 访问 [https://console.groq.com](https://console.groq.com)
2. 注册账号（支持 Google/GitHub 登录）
3. 进入 API Keys 页面
4. 点击 "Create API Key"
5. 复制生成的 API Key

#### 配置 .env 文件

```bash
# 复制示例文件
cp .env.example .env

# 编辑 .env 文件，填入你的 API Key
```

`.env` 文件内容：

```env
# Groq API Key（推荐，完全免费，速度最快）
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxx

# OpenAI API Key（可选，需要付费）
# OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx

# Google Gemini API Key（可选，有免费额度）
# GOOGLE_API_KEY=AIzaxxxxxxxxxxxxxxxxxxxxxxxx

# DeepSeek API Key（可选，国内可用）
# DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

## 第一个 Hello World 程序

让我们编写第一个 LangChain 程序，验证环境是否正确配置。

```python
"""
第一个 LangChain 程序
功能：使用 Groq 调用 LLM，生成一段自我介绍
"""

import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

# 1. 加载环境变量
load_dotenv()

# 2. 验证 API Key 是否配置
api_key = os.getenv("GROQ_API_KEY")
if not api_key:
    raise ValueError("请在 .env 文件中配置 GROQ_API_KEY")

# 3. 初始化模型
# 格式："provider:model-name"
model = init_chat_model("groq:llama-3.3-70b-versatile")

# 4. 调用模型
response = model.invoke("你好！请用中文简单介绍一下自己。")

# 5. 打印结果
print("=" * 50)
print("AI 回复：")
print("=" * 50)
print(response.content)
print("=" * 50)
```

**预期输出示例：**

```
==================================================
AI 回复：
==================================================
你好！我是一个由 Meta 开发的大语言模型，名叫 Llama。我可以帮助你回答问题、
撰写文本、翻译语言、编写代码等各种任务。有什么我可以帮助你的吗？
==================================================
```

```bash

python phase1_fundamentals/01_hello_langchain/main.py
```

## 常见安装问题排查

### 问题 1：`ModuleNotFoundError: No module named 'langchain'`

**原因**：虚拟环境未激活，或依赖未安装。

```bash
# 解决方案：激活虚拟环境后重新安装
source venv/bin/activate  # 或 venv\Scripts\activate (Windows)
pip install -r requirements.txt
```

### 问题 2：`AuthenticationError: Invalid API Key`

**原因**：API Key 未配置或配置错误。

```bash
# 检查 .env 文件是否存在
cat .env

# 确认 GROQ_API_KEY 的值是否正确
# 注意：不要有多余的空格或引号
```

### 问题 3：`pip install` 速度慢或超时

**解决方案**：使用国内镜像源。

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 问题 4：`Python version not supported`

**原因**：Python 版本低于 3.10。

```bash
# 检查版本
python --version

# 如果版本过低，需要升级 Python
# 推荐使用 pyenv（macOS/Linux）或直接下载安装（Windows）
```

### 问题 5：Groq 报错 `Rate limit exceeded`

**原因**：免费账户有速率限制（每分钟请求数）。

```python
# 解决方案：添加重试逻辑
import time

def call_with_retry(model, message, max_retries=3):
    for attempt in range(max_retries):
        try:
            return model.invoke(message)
        except Exception as e:
            if "rate" in str(e).lower() and attempt < max_retries - 1:
                print(f"速率限制，等待 {2 ** attempt} 秒后重试...")
                time.sleep(2 ** attempt)
            else:
                raise
```

### 问题 6：Windows 下 `venv\Scripts\activate` 报错

**原因**：PowerShell 执行策略限制。

```powershell
# 解决方案：以管理员身份运行 PowerShell，执行：
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

# 然后重新激活
venv\Scripts\activate
```

## 最佳实践

1. **始终使用虚拟环境**：避免依赖冲突，保持系统 Python 干净。

2. **API Key 安全**：
   - 永远不要将 `.env` 文件提交到 Git
   - `.gitignore` 中应包含 `.env`
   - 不要在代码中硬编码 API Key

3. **模型选择策略**：
   - 开发测试阶段使用 Groq（免费、快速）
   - 生产环境根据需求选择（质量 vs 成本 vs 速度）

4. **代码组织**：
   - 每个模块独立运行，互不影响
   - 共享工具放在 `tools/` 目录下
   - 使用 `sys.path.insert()` 处理模块导入路径

5. **错误处理**：
   - 总是检查 API Key 是否存在
   - 为 LLM 调用添加超时和重试逻辑
   - 使用 `try-except` 捕获网络错误
